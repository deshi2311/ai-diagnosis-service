## 3. データの流れ（必須一連）

```text
[一般ユーザー]
  LP (/) 
    → (匿名 session cookie aid_sid) landing_viewed
  Googleログイン成功
    → login_completed (sessionId + userId 接続)
  /diagnosis 表示
    → diagnosis_started
  POST /api/diagnosis (answers)
    → diagnosis_answered（バリデーション成功時）
    → Diagnosis.create (_id, userId)
    → diagnosis_completed (diagnosisId)
  /diagnosis/result?id=...
    → result_viewed
  /dashboard
    → 本人の Diagnosis 一覧（userId）

[管理者]
  /admin → GET /api/admin/analytics
    → Diagnosis + AnalyticsEvent 集計
  KPI・推移・分布・最近の結果に同一 diagnosisId / userId が反映
```

### ID受け渡し表

| 段階 | 画面 | API / 処理 | DB | 識別子 |
|------|------|------------|-----|--------|
| LP閲覧 | `/` | `POST /api/analytics/event` | `AnalyticsEvent` | `anonymousSessionId`（Cookie `aid_sid`） |
| ログイン | Google callback | NextAuth `signIn` event | `AnalyticsEvent` + `users` | `anonymousSessionId` → `userId` |
| 診断開始 | `/diagnosis` | event | `AnalyticsEvent` | session + userId |
| 回答 | フォーム送信 | `POST /api/diagnosis` 内 | event | session + userId |
| 完了 | 同上 | `Diagnosis.create` | `diagnoses` + event | `diagnosisId`, `userId` |
| 結果閲覧 | `/diagnosis/result` | event（ページ） | `AnalyticsEvent` | `diagnosisId` |
| 本人dashboard | `/dashboard` | Mongo 直接 or GET diagnosis | `diagnoses` | `userId` |
| 管理KPI | `/admin` | `GET /api/admin/analytics` | 集計 | 期間内の上記 |

### モック禁止

管理画面の数値は MongoDB の実レコード／イベントから算出する。固定ダミー配列のみの完成扱いはしない。

## 4. 画面設計

| パス | 内容 |
|------|------|
| `/admin` | KPI、前日比・前週比、簡易推移、最大離脱地点要約、「ファネル分析を見る」、最近の結果、システム状態、最終更新 |
| `/admin/analytics` | タブ: **全体分析** / **ファネル分析**（`/admin/funnel` は作らない） |
| `/admin/users` | DataGrid: 検索・フィルタ・ページネーション・詳細・ロール変更（確認UI） |
| `/admin/errors` | エラーログ一覧（時刻・種類・影響・対応状況） |

### KPI定義（タイムゾーン: `Asia/Tokyo`）

| KPI | 定義 | 管理者が判断すること | 次アクション例 |
|-----|------|----------------------|----------------|
| 本日の診断数 | 当日0:00≦createdAt＜翌日0:00 の Diagnosis 件数 | 今日の利用が平常か | 急減→エラーログ・診断API |
| 総診断数 | Diagnosis 全件 | 累計成長 | 長期停滞→施策 |
| アクティブユーザー | 期間内に Diagnosis を1件以上持つ distinct userId | 利用者の厚み | 減少→導線・CTA |
| 診断完了率 | completed / started（ファネル同一コホート） | 開始後の完了落ち | 質問負荷・API失敗 |

比較: 前日比・前週比。データ不足時は「比較不能（データ不足）」と理由表示。  
更新: 画面表示時＋手動「更新」ボタン。最終更新時刻を表示。

### 全体分析

- 日/週/月別診断数推移（recharts）
- 強みタイプ分布
- 回答傾向（q1/q2/q3/q5 の簡易キーワード上位）
- 人気キャリアパス TOP10（`suitableJobs` 出現回数）
- 最近の診断結果（id・strengthType・createdAt。回答本文は出さない）
- CSV（期間・粒度を反映、UTF-8 BOM、件数・出力日時・条件をヘッダコメントまたは先頭行メタ）

### ファネル分析（起点コホート）

**既定**: session基準。選択期間内に `landing_viewed` した `anonymousSessionId` を母集団とし、同一sessionの順序付きイベントを **LP閲覧から7日以内** まで追跡。  
期間境界: Asia/Tokyo の `[start, end)`。  
画面に: 対象期間、単位（session）、変換期限、最終更新、空/読込/エラー＋再試行。

| 段階 | イベント | データ源 |
|------|----------|----------|
| LP閲覧 | `landing_viewed` | event log |
| ログイン完了 | `login_completed` | event log（Auth signIn） |
| 診断開始 | `diagnosis_started` | event log（/diagnosis 表示） |
| 回答 | `diagnosis_answered` | event log（POSTバリデーション成功） |
| 診断完了 | `diagnosis_completed` | event log + Diagnosis.create |
| 結果閲覧 | `result_viewed` | event log（結果ページ） |

**注意（現状仕様）**: クライアントは5問を一括送信するため、「回答」と「完了」はほぼ連続。設問単位の途中離脱は **未計測（未確認: 下書きAPIが無い）**。

#### 計測設計表

| 段階 | データ源 | 記録箇所 | 発生条件 | timestamp | 識別子 | 重複排除キー | 失敗時 |
|------|----------|----------|----------|-----------|--------|--------------|--------|
| LP閲覧 | event | `AnalyticsBeacon` on `/` + `POST /api/analytics/event` | LPマウント1回/日・session | サーバー時刻 | anonymousSessionId | `landing_viewed:{sid}:{yyyy-mm-dd}` | 失敗は未計測。再送は同一キーでupsert |
| ログイン完了 | event | Auth `events.signIn` | OAuth成功 | サーバー時刻 | sid+userId | `login_completed:{sid}:{userId}` | ログのみ。導線は次ログインで再試行 |
| 診断開始 | event | `/diagnosis` クライアント | 認証済みページ表示 | サーバー時刻 | sid+userId | `diagnosis_started:{sid}:{userId}:{yyyy-mm-dd}` | 未計測 |
| 回答 | event | `POST /api/diagnosis` | validateAnswers成功直後 | サーバー時刻 | sid+userId | `diagnosis_answered:{sid}:{userId}:{requestId}` | API全体失敗時は未記録 |
| 診断完了 | event+既存 | create後 | Diagnosis保存成功 | createdAt | diagnosisId | `diagnosis_completed:{diagnosisId}` | 保存失敗時はeventなし |
| 結果閲覧 | event | result/detail ページ | 本人の結果表示成功 | サーバー時刻 | diagnosisId | `result_viewed:{diagnosisId}:{userId}` | 未計測 |

#### 方式比較（結論）

| 方式 | 本STAGEの採用 |
|------|----------------|
| event log | LP〜結果の6段階に採用（途中行動がDiagnosis日時だけでは復元不可） |
| 既存日時 | 診断完了の裏取りに `Diagnosis.createdAt` を併用。KPIの診断数は Diagnosis を正とする |

#### 匿名session境界

- Cookie名: `aid_sid`（httpOnly, Secure本番, SameSite=Lax, 30日）
- サーバー発行（`POST /api/analytics/session` または初回event時）。クライアント指定IDは署名/照合できない場合拒否
- ログイン後も **sessionファネルは同一 aid_sid を軸**
- ログアウト時: Cookie再発行（導線クローズ）
- イベントにメール・氏名・回答本文・トークン・Cookie値を保存しない
- 保持: 90日（TTL index）。CSVは集計値と最小限の診断メタのみ

#### 離脱と次アクション（画面表示）

仕様要件どおり LP→ログイン / ログイン→開始 / 開始→回答 / 回答→完了 / 完了→結果 の表を `/admin` 要約とファネルタブに表示。母数少は「参考値」。

## 5. API設計

| メソッド | パス | 権限 | 内容 |
|----------|------|------|------|
| GET | `/api/admin/analytics` | admin | KPI・推移・分布・TOP10・最近・ファネル・システム状態 |
| GET | `/api/admin/analytics/csv` | admin | CSV |
| GET | `/api/admin/users` | admin | 一覧（検索q, role, page, pageSize） |
| GET | `/api/admin/users/[id]` | admin | 詳細（回答本文なし。診断件数・最終診断日） |
| PATCH | `/api/admin/users/[id]` | admin | `{ role }`。自己変更禁止・最後のadmin降格禁止 |
| GET | `/api/admin/errors` | admin | エラーログ |
| PATCH | `/api/admin/errors/[id]` | admin | 対応状況更新 |
| POST | `/api/analytics/session` | public | 匿名session発行 |
| POST | `/api/analytics/event` | public/auth | イベントupsert（PII禁止） |

すべて `/api/admin/*` はサーバー側で `auth()` + DB上の `role==='admin'` を検証（クライアントrole非信頼）。

## 7. セキュリティ

- `/admin` middleware + 各ページ `requireAdmin`
- 管理APIすべてサーバー検証 → 一般は 401/403
- 自己ロール変更禁止、最後のadmin降格禁止
- 危険操作は確認ダイアログ
- Sentry: パスワード・トークン・Cookie・回答全文を送らない（`beforeSend` で除去）。DSN未設定時は無効
- CSVはメールを必要な一覧用途のみ。診断回答全文は出さない

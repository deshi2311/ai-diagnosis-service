# ユーザーニーズ洗い出し

**目的**: LP（Stage1）およびサービス全体のMVP検討に必要なニーズを整理する  
**入力**: ペルソナ定義・ユーザージャーニー・サービス概要

---

## 1. ニーズの分類軸

| 分類 | 説明 |
|------|------|
| Must（必須） | 満たないとLP離脱・診断開始に至らない |
| Should（重要） | 転換率・満足度に大きく効く |
| Could（あると良い） | Stage2以降や差別化で検討 |
| Won't（今回対象外） | Stage1〜MVP初期では扱わない |

## 5. インサイト（ニーズから導く設計方針）

1. **手軽さが第一の購買理由** — 「5問」をヒーローから一貫して強調する  
2. **結果の中身が見えないと押さない** — 「診断でわかること」は抽象ワードではなく項目レベルで書く  
3. **3ペルソナ分の悩みを1セクションでカバー** — 課題提起の3項目は就活／転職／再設計に対応させる  
4. **CTAは理解後と即決の両方** — ヒーロー（即決）と下部（納得後）の2箇所をMustとする  
5. **Stage1は「約束」まで** — 診断ロジック本体はStage2。LPでは約束の明確さと導線完備を優先する  

---

## 6. 非ニーズ（やらないこと）

| 項目 | 理由 |
|------|------|
| 料金プラン表・複雑な会員説明 | Stage1は診断導線に集中 |
| お客様の声の大量掲載 | 実績データ未整備の想定。無理に作らない |
| 求人一覧・エージェント申込 | コア体験（診断）と異なる |
| 長文の自己分析解説コンテンツ | LPの目的外。離脱要因になる |

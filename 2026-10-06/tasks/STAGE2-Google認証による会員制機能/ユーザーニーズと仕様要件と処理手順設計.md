# STAGE2 Google認証による会員制機能

**日付**: 2026-10-06  
**対象サービス**: AIキャリア診断サービス  
**技術**: Next.js 15 / App Router / NextAuth.js v5 (Auth.js) / MongoDB Adapter / MUI / JWT セッション

---

## 1. ユーザーニーズ

### 1.1 背景

Stage1 の LP は誰でも閲覧できる。診断や結果の保存は「会員であること」が前提になる。まずは **Google アカウントだけで入れる会員基盤** が必要。

### 1.2 だれの何を満たすか

| ユーザー | ニーズ | 本機能での応え方 |
|----------|--------|------------------|
| 就活・転職検討中の利用者 | 面倒な会員登録をしたくない | Google ワンクリックログイン |
| 同じ利用者 | 自分の情報が見える安心感がほしい | ダッシュボードで名前・アバター表示 |
| 同じ利用者 | 表示名を変えたいことがある | プロフィール編集・保存 |
| 未ログイン利用者 | 会員ページに入れないこと | `/dashboard` `/profile` を保護し、ログインへ誘導 |
| 運営 | ユーザーを永続化したい | MongoDB Adapter で User を保存 |

### 1.3 非ニーズ（今回やらないこと）

- メール／パスワード登録
- 診断本体（Stage3）
- メールアドレスの変更（Google 側の値を正とする）
- アバター画像のアップロード（Google 画像を表示）

## 2. 仕様要件

### 2.1 認証

| 項目 | 仕様 |
|------|------|
| ライブラリ | NextAuth.js v5（Auth.js） |
| プロバイダ | Google OAuth |
| セッション | **JWT 方式**（Cookie に JWT。DB セッションは使わない） |
| ユーザー保存 | **MongoDB Adapter**（User / Account を MongoDB に保存） |
| 環境変数 | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `AUTH_SECRET`（接続用に `MONGODB_URI` も必須） |

JWT と Adapter は併用する。

- Adapter: 初回ログイン時に User を MongoDB へ作成し、以降のプロフィール更新先にする
- JWT: リクエストごとのログイン判定を DB 照会なしで行う

### 2.2 画面

| パス | 認証 | 内容 |
|------|------|------|
| `/auth/signin` | 不要（ログイン済なら `/dashboard` へ） | Google ログインボタン。成功後は `/dashboard` |
| `/dashboard` | **必須** | 会員トップ。名前・アバター。ナビ（トップ / ダッシュボード / プロフィール / ログアウト） |
| `/profile` | **必須** | 名前・メール・アバター表示。名前の編集フォームと保存 |

未ログインで保護ルートへ来た場合は `/auth/signin` へリダイレクト。

UI は MUI の `Button` / `Card` / `Avatar` / `TextField` を使う。

### 2.3 API

| メソッド | パス | 認証 | 内容 |
|----------|------|------|------|
| GET / POST | `/api/auth/[...nextauth]` | NextAuth 管理 | 認証エンドポイント |
| GET | `/api/user/profile` | 必須 | ログイン中ユーザー情報を返す |
| PUT | `/api/user/profile` | 必須 | プロフィール（名前）を更新 |

未認証 API は `401`。

### 2.4 ミドルウェア

対象: `/dashboard` とその配下、`/profile` とその配下。  
未ログイン → `/auth/signin`（必要なら `callbackUrl` を付与）。

### 2.5 データモデル（User）

NextAuth.js デフォルト + 拡張。MongoDB `users` コレクション。

| フィールド | 型 | 説明 |
|------------|-----|------|
| `_id` | ObjectId | 主キー |
| `name` | string | 表示名（編集可） |
| `email` | string | Google のメール（編集不可） |
| `image` | string | Google アバター URL |
| `emailVerified` | Date | NextAuth 既定 |
| `createdAt` | Date | 作成日時（拡張） |
| `updatedAt` | Date | 更新日時（拡張） |

### 2.6 受け入れ条件

- [ ] Google でログインでき、`/dashboard` に着地する
- [ ] 未ログインで `/dashboard` `/profile` を開くと `/auth/signin` に飛ぶ
- [ ] ダッシュボードに名前とアバターが出る
- [ ] プロフィールで名前を保存すると反映される
- [ ] セッションは JWT、User は MongoDB に残る
- [ ] LP（`/`）は従来どおり未ログインでも見られる

## 3. 処理手順設計

### 3.1 全体フロー（ログイン）

```
利用者                 アプリ                    Google                 MongoDB
  |                      |                         |                      |
  |  /auth/signin        |                         |                      |
  |  Googleでログイン     |                         |                      |
  |--------------------->| signIn("google")        |                      |
  |                      |------------------------>| 同意画面             |
  |                      |<----- 認可コード --------|                      |
  |                      | プロフィール取得         |                      |
  |                      |----------------------------------------------->| User upsert
  |                      | JWT Cookie 発行         |                      |
  |  302 /dashboard      |                         |                      |
  |<---------------------|                         |                      |
```

### 3.2 保護ルート

1. `middleware.ts` が `/dashboard` `/profile` をマッチ
2. JWT Cookie を検証（`auth()`）
3. 無効・未ログインなら `/auth/signin?callbackUrl=...`
4. 有効ならページ描画。ページ側でも `auth()` を再確認

### 3.3 プロフィール取得（GET `/api/user/profile`）

1. セッションから email / id を取る
2. MongoDB `users` を検索
3. なければセッションの値を返す
4. `{ id, name, email, image, createdAt, updatedAt }` を JSON で返す

### 3.4 プロフィール更新（PUT `/api/user/profile`）

1. ログイン必須。body は `{ name: string }`
2. `name` をトリムし、1〜50文字でなければ `400`
3. `users` を email または `_id` で `$set { name, updatedAt }`
4. 成功 JSON を返す
5. クライアントは `session.update({ name })` で JWT 側の表示名も同期

### 3.5 JWT コールバック

| タイミング | 処理 |
|------------|------|
| 初回ログイン `user` あり | `token.id / name / email / picture` をセット |
| `trigger === "update"` | クライアントから渡された `name` を JWT に反映 |
| `session` コールバック | `session.user.id` などを token からコピー |

### 3.6 画面コンポーネント

| コンポーネント | 役割 |
|----------------|------|
| `SignInCard` | ログインページの Card + Google Button |
| `MemberHeader` | 会員画面のナビ（Button / Avatar） |
| `ProfileForm` | TextField（名前編集・メール読み取り専用）と保存 Button |
| `AuthSessionProvider` | `SessionProvider` でアプリ全体を包む |

### 3.8 環境変数

| 変数 | 用途 |
|------|------|
| `GOOGLE_CLIENT_ID` | Google OAuth クライアント ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth シークレット |
| `AUTH_SECRET` | JWT 署名用シークレット |
| `MONGODB_URI` | MongoDB 接続文字列（Adapter 用） |
| `AUTH_URL` | 本番のアプリ URL（任意。Vercel では `AUTH_TRUST_HOST=true`） |

Google Cloud Console のリダイレクト URI 例:

```
http://localhost:3000/api/auth/callback/google
https://<本番ドメイン>/api/auth/callback/google
```
